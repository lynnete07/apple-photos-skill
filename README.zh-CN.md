# Apple Photos Agent Skill

[English](README.md)

这是一个带安全门禁的 Apple Photos skill，帮助用户整理大型照片库，同时减少重复、细碎的决策。

它按年度分析照片库，将照片划分为复核批次，复用已有相册，创建经过覆盖校验的年度兜底相册，把“收藏”作为中性选择标记，导出未修改原件，并且只执行用户明确确认的删除方案。

## 适合哪些用户

- Apple Photos 中积累了多年、大量照片与视频的人。
- 喜欢明确规则和可预测流程的人，包括神经多样性用户，以及容易产生决策疲劳的人。
- 使用 Codex、Claude Code、WorkBuddy 或其他兼容 Agent Skills 的本地 Agent 的人。

## 主流程

1. **分析**：根据拍摄时间、频次、位置和设备连续性识别批次，不修改 Photos。
2. **隔离**：复用完整覆盖批次的已有相册；建立互不重叠的复核相册；校验年度兜底相册。
3. **标记**：把收藏作为任意子集的临时标记。收藏不自动等于保留或删除。
4. **执行**：只执行已经确认的保留、导出、删除、合并或结束批次方案。
5. **复核**：每次修改前后重新读取当前内容和精确数量。

指令中的“照片”默认包括静态照片、视频和 Live Photo。导出使用未修改原始资源，保留内嵌元数据。Live Photo 默认导出静态原片与配对动态资源；只有用户明确选择时才只导出静态图片。

本 skill 仅使用 Apple 公开 PhotoKit API，不读取或修改 Photos 私有数据库。

## 环境要求

- 安装 Apple Photos 的 macOS。
- Xcode Command Line Tools，能够使用 `xcrun` 和 Swift 编译器。
- Python 3。
- 能加载 Agent Skills 并执行终端命令的本地 AI Agent。
- macOS 请求权限时，允许访问完整照片图库。

所有处理均在本机运行。本 skill 不会自行上传照片或元数据。

## Agent 兼容性

完整的 `apple-photos/` 文件夹遵循开放的 Agent Skills 目录结构。`SKILL.md` 是权威工作契约；`scripts/` 和 `references/` 存放执行程序与参考资料。`agents/openai.yaml` 只是 Codex 的可选适配文件，其他 Agent 不依赖它。

| Agent | 安装方式 |
|---|---|
| Codex | 将 `apple-photos/` 复制到 `~/.codex/skills/apple-photos/`，然后重启 Codex。 |
| Claude Code | 安装到 `~/.claude/skills/apple-photos/`，或项目内的 `.claude/skills/apple-photos/`。使用 `/apple-photos` 调用。 |
| WorkBuddy | 下载 Release ZIP，通过 **添加 Skill → 上传 Skill** 导入。 |
| 其他 Agent | 将完整文件夹安装到产品的 Agent Skills 目录，或先要求 Agent 读取 `apple-photos/SKILL.md`。 |

Agent 必须运行在持有照片图库的 Mac 上，或连接到已取得 Photos 权限的可信 macOS 执行环境。详细说明见 [Agent 兼容性](docs/AGENT-COMPATIBILITY.zh-CN.md)。

## 用自然语言开始

使用当前 Agent 支持的 skill 名称或调用方式：

```text
使用 apple-photos skill 分析我 2026 年的所有照片和视频。本轮只分析，不创建或删除任何内容。
```

```text
按照已确认方案创建 2026 年复核相册，并创建一个兜底相册，承载所有未进入批次且未被已有相册覆盖的 2026 年内容。
```

```text
删除相册【2026-05-16_家庭聚会】中未收藏的内容，保留相册，并确认收藏内容没有受到影响。
```

```text
将相册【2026-09-12_毕业典礼】的未修改原件导出到我的归档位置。Live Photo 导出完整原始资源，不删除任何内容。
```

## 分析结果中的相册命名规则

分析阶段给出的名称是可编辑建议，不是系统强制标识。默认格式为：

```text
YYYY-MM-DD_<标签>
```

- 日期取批次中最早的 Photos 拍摄日期，并按 Mac 当前本地时区解释。
- 用户确认或证据充分的事件使用具体主题，例如 `2026-05-16_家庭聚会`。
- 主题不明的单次集中拍摄默认使用 `待识别主题`。
- 主题不明的跨日或多高峰批次默认使用 `待识别连续段`。
- 年度兜底相册默认使用 `YYYY_未进入批次`。
- 已有相册完整覆盖批次时，复用现有名称，不重复创建相册。

分析结果会展示建议名称、拍摄范围、内容数量、判断依据、置信度、已有相册覆盖情况，以及名称是否可以修改：

| 建议相册名 | 拍摄范围 | 数量 | 判断依据 | 置信度 | 可修改 |
|---|---|---:|---|---|---|
| `2026-05-16_家庭聚会` | 05-16 10:12—18:46 | 63 | 单日高频拍摄，用户确认事件 | 高 | 是 |
| `2026-09-02_待识别连续段` | 09-02—09-04 | 118 | 连续三日，主题不明 | 未知 | 是 |
| `2026_未进入批次` | 全年剩余内容 | 27 | 年度覆盖校验后的剩余集合 | 固定功能 | 是 |

创建前，用户可以修改单个名称，也可以统一修改命名模板、语言、分隔符、日期前缀或兜底相册名称。最终 manifest 会原样使用用户确认的名称；内容选择不依赖名称文字。

如果用户之后在 Photos 中手动改名，Agent 必须在下一次操作前重新读取当前名称，并更新尚未执行的队列或 manifest。完整规则见 [相册命名规范](apple-photos/references/album-naming.md)。

## 公共版安全默认值

| 设置 | 默认值 |
|---|---|
| 导出后的 Photos 原资产 | 保留 |
| 电脑或外置盘来源 | 保留 |
| RAW 文件 | 归档并保留 |
| Live Photo | 导出静态原片与配对动态资源 |
| 归档路径 | 不预设，由用户提供 |

配置文件不能代替本次破坏性操作的明确授权。

## 安全规则

- 删除 Photos 资产会从图库全局删除，不只是移出当前相册。
- 删除内容会进入“最近删除”。恢复资产不会自动恢复已经删除的相册结构。
- 相册名称必须唯一匹配。
- 数量变化、权限被拒绝、iCloud 原件下载失败、相册重名或复核失败时，操作立即停止。
- 导出和删除可以放入同一个方案，但只有选中原件全部导出并验证后才会开始删除。

第一次执行删除前，请阅读[安全模型](docs/SAFETY.zh-CN.md)。

## 能力边界

- 本 skill 处理 PhotoKit 能访问的系统照片图库。
- 仅存在于 iCloud 的原件必须能够下载，导出才能完成。
- Finder 创建时间不是拍摄时间。本 skill 保留文件内嵌元数据，并单独报告 Photos 显示的拍摄日期。
- 归档比对使用 SHA-256，默认包含所有格式；只有用户明确要求时才忽略某种格式。
- 本 skill 不根据画面擅自推断人物、事件或旅行名称，只根据元数据提出批次，并请用户确认不确定的名称。

安装或转发时，请保持 `apple-photos/` 文件夹内部结构不变。版本和贡献说明见 [CHANGELOG.md](CHANGELOG.md)、[CONTRIBUTING.md](CONTRIBUTING.md) 和 [SECURITY.md](SECURITY.md)。
